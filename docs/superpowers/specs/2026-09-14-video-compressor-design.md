# Windows 视频压缩工具设计提案

状态：用户已确认并授权实现；配色按后续要求改为浅色、非纯白。

## 目标与选型

面向 Windows 10/11 x64，提供中文、本地离线的批量视频压缩工具。重点兼容 NVIDIA App / ShadowPlay 和 OBS 录制的视频；用户所说的“适配 N 卡”指录屏输入兼容性，并非要求 NVIDIA 硬件加速。尽量保留可感知画质，输出普通 MP4 文件。2K 在本项目定义为 2560×1440。

推荐 Tauri 2 + React + TypeScript + Rust + FFmpeg/ffprobe。React 负责界面；Rust 负责输入校验、文件操作、任务调度和子进程生命周期；FFmpeg 负责实际编解码。Windows 便携 ZIP 携带固定版本 FFmpeg/ffprobe 和 WebView2 运行库，不提供安装器。解压后直接运行，不要求安装运行库。最终 ZIP 体积以实测为准，不能用纯 Tauri 空壳大小代表含 FFmpeg 的成品。

备选：WPF/.NET 适合纯 Windows 原生应用，但界面实现方式与当前 macOS 开发环境不匹配；Electron 的 Web 环境更统一，但自带 Chromium 的基础开销更大。本项目选型是对界面开发、资源占用和可验证性的权衡，不宣称存在所有维度都最优的框架。转码速度主要由编码器、参数、显卡和视频决定。

## 界面与使用流程

采用浅灰底色、略亮的灰色面板、低饱和蓝紫强调色、清晰文字层级和适量留白，避免纯白背景。单窗口布局：顶部显示应用名称及硬件状态；左侧大区域为拖入文件和批量队列；右侧固定设置面板；底部为总进度和开始/停止操作。空队列提供明确的文件导入入口，不填充虚假任务或虚假压缩数据。

1. 拖入或多选文件，读取时长、分辨率、帧率、编码、音轨和大小。
2. 选择输出目录、分辨率、帧率、质量和编码方式，默认应用于整批。开始时冻结该批参数，避免处理中改动影响结果。
3. 开始处理；显示每项状态、当前进度、速度、预计剩余时间和错误原因。
4. 完成后显示实际输出大小、节省比例和打开所在文件夹入口。输出更大时明确显示，不声称压缩成功节省空间。

## 输出与质量策略

- 输出统一为 .mp4。默认 H.264 + AAC、8-bit yuv420p，优先普通播放器兼容；可选 H.265/HEVC 以争取更小体积，界面说明播放设备需要 HEVC 支持。
- 编码设备支持自动、NVIDIA GPU、CPU。自动模式先实际短编码探测，不能仅凭编码器名称存在就认定 GPU 可用。不可用时显示原因并回退 CPU；显式选择 NVIDIA 时失败应提示，避免无声切换。
- 硬件解码和硬件编码分别检测。源格式不支持硬件解码时可采用软件解码加 NVENC 编码；不因单一环节不支持就放弃全部加速。
- 质量提供高画质、均衡、更小体积三档，默认高画质；软件采用 CRF、NVENC 采用质量目标控制。两类编码器的质量数值不直接等价，预设必须分别校准。
- 软件慢速编码模式面向愿意等待以争取压缩效率的用户；GPU 模式面向处理效率。不同显卡代际和内容表现以实测为准。
- 分辨率支持原始、720p、1080p、1440p（2K）；按目标边界等比缩小、不裁切、不拉伸、不自动放大。竖屏交换边界，宽高对齐到编码要求。
- 帧率支持原始、30、60、自定义 1–240，可输入 29.97 等小数。选择原始保留输入时间信息；指定帧率转为对应恒定帧率。升帧仅复制帧，不承诺运动插帧效果。
- NVIDIA App / ShadowPlay 和 OBS 录屏为重点输入来源。按文件真实元数据识别容器、编码、帧率、色彩和音轨，不根据录制软件名称推断格式。兼容测试覆盖 MP4/MKV、H.264/HEVC/AV1、高码率游戏画面、可变帧率及多音轨；这些是测试范围，并不代表每种录制软件都支持所有组合。默认保留全部音轨及标题/语言信息；兼容 AAC 直接复制，其余转 AAC，不将音轨隐式混音。
- 检测 HDR/10-bit：默认兼容输出需要明确进行 HDR→SDR 色调映射；HEVC 模式可选择保留受支持的 HDR 信息。未经正确处理不得悄悄输出偏色画面。
- 不保证固定压缩比例或数学无损。对已经高效压缩的源文件，输出可能更大；始终保留源文件。

## 队列、文件与错误处理

默认单任务转码，限制资源争用；支持多文件排队、移除等待项、停止后续队列、取消当前任务和重试失败项。首版不实现当前编码进程暂停后续传。

任务状态为探测中、待处理、处理中、校验中、完成、失败、已取消。读取 FFmpeg 结构化进度，以源时长计算；未知时长显示不确定进度，不伪造百分比。失败不阻塞剩余队列。

输出默认独立目录，重名自动编号，禁止覆盖输入或已有结果。转码写入任务专属临时文件；只有进程成功且 ffprobe 检查通过后才更名为最终 MP4。取消或失败只清理该任务的临时文件。使用参数数组启动子进程，正确处理中文、空格及特殊字符路径。关闭窗口时明确处理活跃进程，避免孤儿 FFmpeg。

保存最近使用的设置与目录。完整错误日志可在详情查看；磁盘不足、权限不足、无视频流、损坏文件、驱动不兼容分别给出可操作提示。

## 组件边界

- UI：导入区域、任务列表、设置面板、进度摘要、错误详情。
- 媒体探测：ffprobe 元数据解析和 GPU 能力短测。
- 编码计划：输入元数据与设置转换为确定的参数，集中处理缩放、帧率、音轨与色彩。
- 队列执行：调度、取消、进度事件、错误记录。
- 输出管理：安全命名、临时文件、校验和最终更名。
- 发布：固定依赖、FFmpeg 二进制校验和相应许可证材料、Windows 构建及安装说明。

## 验收与交付

自动化测试覆盖缩放比例、竖屏、帧率校验、编码器回退、音轨映射、命名冲突、取消清理与批量失败隔离。使用真实短视频执行转码，核对尺寸、时长、帧率、音轨、文件大小并解码检查；对游戏运动画面及文字录屏做视觉抽查，质量指标仅作为辅助。

界面检查覆盖空状态、多文件、长文件名、处理中、失败与完成状态以及 Windows 高 DPI。Windows 核心验收覆盖安装启动、WebView2、中文路径、NVIDIA App / ShadowPlay 录屏与 OBS 多音轨录屏的实际转码和播放。NVIDIA 硬件加速属于可选优化，另行检查真机转码和 CPU 回退；没有 NVIDIA 显卡也应能够压缩这些录屏文件。

当前开发主机为 macOS，可验证前端和跨平台核心，但 Windows 便携 ZIP 及 NVIDIA 加速必须有 Windows 构建与真机证据才能宣称验证通过。交付应明确区分源码完成、本机验证和 Windows/NVIDIA 实测状态。
